# Architecture

## A narrative over evidence

A **Project** represents a repository or product. A **BuildEntry** describes meaningful work and belongs to a project. Entry kinds are feature, improvement, fix, release and learning; learning is included deliberately because building also involves discoveries. An entry carries an author origin and owns zero or more **SourceActivity** records. Commits and pull requests remain source evidence rather than becoming one entry each. User-authored entries contain no fabricated source data.

**JournalSummary** supports daily/weekly periods and manual/generated-draft origins, with input entry IDs for provenance. V1 exposed handwritten daily reflections. V2 caches generated daily narratives, with a distinct edited-generated origin and exact source IDs. Empty reflection text removes the reflection; it never creates output or affects statistics. Existing handwritten text must not be silently replaced by future generation.

The schema is versioned from the first build. `ShiplogSchemaV1` must remain frozen after release. Future model changes belong in a new schema and explicit migration stages. Deleting a project cascades its entries and their evidence; date reflections are independent and are retained. Archive preserves history and excludes the project from new-build selection and active-project statistics.

## State and persistence

One SwiftData container is injected at the app root. SwiftUI queries provide observation; screen-local `@State` owns editor drafts, sheets and search. There is no redundant view-model layer. Editors validate before mutating stored objects. All production mutations use explicit saves; a persistence failure rolls back the operation and displays recovery text without discarding the draft. Store boot failure never switches silently to an ephemeral store or erases the database.

SwiftData models stay on the main actor. Immutable, Sendable `EntryRecord` values cross future asynchronous service boundaries. Pure domain arithmetic accepts the clock and calendar explicitly, making DST and time-zone behavior testable. Day grouping and streaks use calendar days rather than 24-hour intervals. A current streak may end yesterday; it expires after an entire missed day. Multiple entries on one day count once. Future-dated entries are excluded. This-week counts follow the user's calendar week; active projects means unarchived projects with entries this week.

Reflections are keyed by a civil date. Entries are grouped by the user's current local calendar, so travel can change their day grouping. Manual journaling requires no background task, notification permission, credential, or network access. Connecting GitHub explicitly opts into the server agent. The Today clock updates on foreground and while visible; Insights periodically recalculates local week boundaries.

## GitHub-first agent

The `backend` service owns GitHub App private keys, encrypted user/refresh tokens, repository-scoped installation tokens, model credentials, evidence, job leases, and server journals. The iPhone uses `ASWebAuthenticationSession`, a one-time PKCE-bound exchange, a device-only Keychain bearer, and `AgentClient`. GitHub App repository selection occurs in the authenticated browser flow and is revalidated through the user-access-token/installation intersection. Redirect installation IDs are never trusted. Only opted-in repositories are imported; patches are separately optional. Native provider orchestration is deliberately not required.

Webhooks verify their raw-body HMAC before parsing. Unselected repository events are discarded. Normalization attributes source work to explicit GitHub author/committer or timeline-actor IDs; user display names/emails and PR `updated_at` are insufficient proof. Durable delivery records and periodic branch/issue reconciliation recover missed/interrupted events, with a bounded seven-day backfill from the last checkpoint. A cached, bounded repository context provides semantic information without whole-repository uploads. Limits fail explicitly, not as partial-success journals.

`JournalSynthesisService` sits between repository context/evidence/existing saved state and meaningful build entries plus a daily narrative. It is separate from the original `SummaryService` contract over already-authored `EntryRecord`s. Structured model output must cite exact evidence IDs. Validation rejects invented IDs, cross-repository citations, duplicate assignment, invalid confidence, unsupported narrative citations, and reuse of protected work. Repository content is untrusted data without model tools or secrets. Confidence is an uncalibrated model estimate, and semantic accuracy still requires live evaluation; citations alone do not prove each sentence.

Generation is scoped by user + civil day + time zone + canonical input hash + prompt version. PostgreSQL JSON key ordering does not affect identity. Evidence overlap retains work-item IDs as new activity arrives; edited entries reserve their old evidence, deleted entries suppress it, and narrative edits are preserved. Queued jobs use atomic claims, retry delays, and lease-token fencing so interrupted workers cannot publish stale results. GitHub authorization/installation removal disables imports. The server handles selected-time finalization and periodic reconciliation; no exact iOS background execution is assumed. APNs is not implemented.

## V2 persistence and synchronization

V1 model declarations remain frozen. An explicit V1-to-V2 migration preserves project/entry/source relationships and handwritten summaries, then upgrades legacy source identities using their available repository URL (or `legacy`) without inventing numeric GitHub repository IDs. New `SourceActivity` construction requires provider, repository, event kind, and provider ID and percent-encodes every identity component.

V2 adds `ConnectedRepository`, `SyncCheckpoint`, `GenerationRun`, and `JournalMutation`, plus remote ownership, exact evidence IDs, confidence, and generation metadata on entries/summaries. The original owned-source relationship is retained for V1/user-imported records. New generated entries refer to neutral evidence through stable IDs, allowing the same evidence to support history across civil-day/time-zone views without reparenting an owned source. Export format 2 includes all cache/provenance/outbox records, excluding credentials.

`JournalSyncStore` validates an immutable `AgentJournal` before mutating SwiftData. It matches existing projects by canonical repository URL while preserving project names/notes. Successful snapshots retire obsolete unedited drafts only for that generation; pending jobs preserve the last good cache. Handwritten and edited-generated text remains authoritative. Every local generated edit/deletion is saved together with a persistent outbox mutation; server acknowledgments are idempotent even after response loss. Pending changes suppress stale incoming drafts. The native transport rejects redirects so credentials/edits remain on the configured HTTPS origin.

The app uploads queued edits before downloading results. A paged server history feed and an overlap watermark recover days written with the phone closed. Foreground refresh reads saved results; Analyze today/pull-to-refresh requests reconciliation and synthesis. Time-zone changes update the server's schedule when the app reconnects. Cancellation and provider/persistence errors leave saved writing available and show recovery text.

## Data and privacy

Manual entries remain local. A GitHub connection requires explicit repository selection and consent to storing metadata, bounded README/manifest/architecture excerpts, commit/PR/issue content, changed filenames, and statistics on Shiplog's Vercel/Neon backend and sending bounded context to OpenRouter and its selected model provider. Code patches are optional, sensitive file patterns are excluded, and provider routing denies prompt-data collection. These controls minimize data; they do not guarantee that selected prose has no sensitive material. Generated-text edits synchronize so the server preserves them. Read the chosen provider's retention terms before live private-repository use.

Disconnect stops imports/jobs, invalidates sessions, and removes stored GitHub credentials while retaining server history. Account deletion cascades user-owned remote records; local journal copies remain. GitHub App installation permissions are revoked separately in GitHub. Processed delivery payloads are cleared and operational delivery IDs expire after seven days. Local export remains user-initiated through the system share sheet. Normal device protection/backups apply to SwiftData; bearer tokens use device-only Keychain storage.

The manifest declares optional linked user identity and other user content for app functionality, with no tracking. The public privacy policy and App Store Connect responses must be updated and reviewed against the actual deployed services before the next public build. No live authorization, provider accuracy/latency, production scheduler delivery, notification, or physical-device acceptance is implied by local verification. See [backend setup](../backend/README.md).
